# 边界与红线：密钥、临时文件、服务、测试数据

## 一、绝不提交

- **密钥与本机配置**：`.env.local`（含自动登录口令）、`.env.*.local`、`.env.development.local`
- **生成物**：`node_modules/`、`dist/`、`coverage/`、`*.tsbuildinfo`、`.eslintcache`、`test-results/`。
- **自动生成且已被跟踪**的文件（常见是 `auto-imports.d.ts` / `components.d.ts`）：不要手工改，
  也不要把它们的 diff 单独夹带进无关提交；随组件变更一起出现时，确认只是生成结果再 `git add`。
- **本机 Claude 配置**：`.claude/` 下只入库 `rules/` 与 `skills/` 两处（`.gitignore` 已开例外），
  `.claude/worktrees/`、`.claude/launch.json` 这类本机设置不入库。
- 走查截图、临时脚本、一次性数据文件。

## 二、临时工具用完即删

为这一步才写的一次性脚本、临时预览页、一次性 SQL、临时图片数据，**在创建它的当下就记住它，用完立即删**。

- 中间产物放 `/tmp`（或 `$TMPDIR`），不要写在仓库里；中文提交信息用 heredoc 喂 `git commit -F -`，不需要临时文件。
- 以后要反复用的东西就不是临时工具：回归脚本放正式位置、可复用流程做成技能、长期约定写进 `.claude/rules/`。
- 为跑通某一步临时改的配置或数据，用完必须还原。

## 三、服务只在当前会话的终端里起

- 长驻进程留在当前会话终端里前台跑，用户能看日志、能接管、能停。
- **禁止** `nohup` / `&` / `disown` / `setsid` / `systemd-run` / `docker run -d` 这类"先撒手再回来"的写法。
- 收工时告诉用户还占着哪些端口、在哪个终端停。
- 浏览器验证用当前会话实际可用的浏览器 MCP；**不要用 `Page.reload` 刷新**（改用导航工具重新导航）。

## 四、测试数据只有一处出处

- 要自然人 / 企业身份、银行卡、结算账户的测试，数据一律取根仓 `docs/测试指南/测试数据`；
  **文件里没有的身份先问用户，不要临编一个「看着像」的**。
- 本机开发库账号口令统一 `Test@123456`（根仓 `.claude/rules/dev-accounts.md`）；
  `.env.local` 里的明文口令只在本机，永不入库、不进对话。

## 五、汇报纪律

- 没有证据不算完成：改了哪些文件（`git status --porcelain` / `git diff --stat`）、
  校验命令的真实输出、行为证据（接口响应 / 截图）三样至少要有两样。
- 没做的写成「下一步」，不要只留在对话里，更不要用"应该没问题"代替验证。
