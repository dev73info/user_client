# 界面文案：不写解释性说明

> 正本：根仓 `.claude/rules/ui-copy.md`。口径是用户定的（2026-10-16 再次强调）：
> **页面上不写解释性说明文案。**

## 一、不许写（解释性说明）

- 区块标题下的一整段说明（「这个配置是干什么的」「为什么这么设计」）。
- 字段下方解释行为或背景的段落（「关闭时，同一买家第二次下单会被拒」）。
- 复述控件自身含义的话（标签已经写了「允许重复购买」，不要再解释这个开关）。
- 用「说明 / 介绍 / 提示」口吻写的产品背景与责任边界。

## 二、允许留（只有这几类）

| 类型 | 例子 |
| --- | --- |
| 字段标签 / 按钮文案 | 「回调地址」「保存」 |
| 占位符（形态示例） | `https://shop.example.com/73info/callback` |
| 校验错误 | 「当前不合法：xxx」「请填 http(s) 绝对地址」 |
| 当前状态值 | 「当前：未生成」「当前：sk\*\*\*1b」 |
| 一次性 / 破坏性操作的必要警示 | 「回调密钥（只显示这一次，请立即复制保存）」 |
| 空态 / 错误态 / 阻塞态 | 「配置还没配齐，暂不可被下单」 |
| 可复制的接入示例（curl 片段） | 给开发者照抄的代码，不是界面介绍 |

## 三、写代码时自检

新增的每个提示元素（`.hint`、`el-alert` / `n-alert` 常驻文案、表头说明）都要能回答：
**它是「错误」「状态」还是「必要警示」？** 三者都不是，就删掉。

- **不要照抄既有页面的说明段当范本**——存量页面里就有这类文案，照抄会把毛病扩散。
- 改到哪一页，就把那一页的解释性文案顺手删掉（只删文案，不动逻辑）。
- 真觉得某句非留不可（例如平台与开发者的责任边界），**先问用户**，不要自己加回去。
- 背景该写到 `doc/`、接口文档或需求/任务文件里，不写在界面上。
