先读这三份，它们是判据来源，不要凭印象：

- `E:\yl73info\user-client\.cursor\rules\design-tokens.mdc`（令牌、档位、断点、移动端要求）
- `E:\yl73info\user-client\.cursor\rules\ui-73info-components.mdc`（组件库口径）
- `E:\yl73info\user-client\doc\设计规范.md`（完整版，含全部令牌取值与文件职责）

## 审查范围

默认审当前未提交的改动（`git diff` 与 `git diff --staged`，含未跟踪的新文件）。
如果调用方给了具体文件路径，就只审那些文件。判断文件是否属于本端：只审 `user-client` 仓库内的文件。

## 逐条检查

1. **体系是否套对**：新页面属于门户还是开发者？门户用无前缀 / `--portal-*`，开发者用 `--dev-*`。
   判据是路由挂在哪——`src/router/dev.ts` 里的是开发者体系。**出现了第三套令牌前缀就是问题。**
2. **有没有裸色值**：页面自己的样式里写 `#rrggbb` / `rgba(...)` 而不是令牌。例外只有文档登记为「页面级令牌」的那几处（如 `--profile-*`）。
3. **圆角与字号**：圆角只能从 `12px` / `10px` / `8px` / `999px` 里选；字号落在 `11–18px`，不得引入 `10px` 以下或 `20px` 以上。
4. **容器宽度**：是否自造了新的 `max-width`，而不是继承 `min(1280px, calc(100% - 24px))` / `min(1120px, 100%)`。
5. **断点**：新增的媒体查询是否只用 `980 / 900 / 780 / 640`。出现别的值就是问题（存量债不算，但改动碰到的行要指出）。
6. **滚动容器**：页面内是否多套了一层滚动容器（会让外壳的 `sticky` 失效）。
7. **移动端**：`640px` 以下的按钮 / 列表项 / 菜单项有没有 `min-height: 44px`；贴边固定元素有没有 `env(safe-area-inset-*)`。
8. **组件库**：有没有出现 `element-plus` / `<el-*>` / `@element-plus/icons-vue` / `ElMessage` / `ElMessageBox`；
   有没有覆写 `.t73-*` 内部类名；库组件的外观是不是优先用了 `tone` / `variant` / `size`；
   有没有给库组件写 `--dev-*` / `--portal-*` 覆盖（那些变量已无组件在读）。
9. **主题属性**：页面里有没有自己去写 `<html>` 的 `data-73-theme`（应该只由 `src/router/index.ts` 的守卫设置）。
10. **数字**：金额与计数有没有 `font-variant-numeric: tabular-nums`。
11. **副标题**：标题下有没有加装饰性副标题（不承载状态、倒计时、口径、必填提示的，就该去掉）。
12. **富文本**：新增的富文本渲染有没有经 `src/utils/sanitizeHtml.ts`。
13. **热调样式**：库组件内部规格该走 `--73-*`，页面自己那层才走 `--dev-*` / `--portal-*`。

## 输出格式

按严重程度分组，每条给出：

- **文件与行号**（`路径:行号`）
- **违反的是哪条**（引用上面的编号与规则文件名）
- **具体改法**（能直接照着改的一句话或一小段代码）

分三档：**必须改**（套错体系、裸色值、写了 Element Plus、覆写 `.t73-*`）、**建议改**（档位外的值、多套滚动容器）、
**待确认**（看起来可疑但可能是页面级例外，说明你为什么不确认）。

没有发现问题就直说「未发现违规」，并列出你实际检查了哪些文件——**不要为了凑数编问题**。
