## 一、这一端有两套视觉体系

这是本文件最重要的一节。同一个 SPA 里并存两套外观，新页面一旦套错令牌，就会看起来「像是另一个网站」。

| 体系 | 覆盖范围 | 令牌前缀 | 归属文件 | 主色 |
| --- | --- | --- | --- | --- |
| 门户 | 首页、需求大厅、资源、社区、个人中心、工作台外壳 | 无前缀（`--accent` 等）与 `--portal-*` | `src/styles/resource-core.css`、`src/styles/home.css` | `#1f4ad1` |
| 开发者 | 开发者工作台、资源管理、需求详情、钱包 | `--dev-*` | `src/styles/dev-base.css` | `#1f4ad1` + `#2aa6a4` + `#b9812b` |

两套都用蓝色 `#1f4ad1` 做主色，区别在气质：门户侧是冷灰白底 + 大圆角卡片，开发者侧是**冷白底**（`--dev-surface` 已是纯白，**不带暖调**）+ 青绿与金色做辅助强调。

**硬规则：不要新建第三套令牌。** 拿不准新页面属于哪一套时，看它的路由挂在哪：`src/router/dev.ts` 里的是开发者体系，其余是门户体系。

另有一处**页面级**令牌，它只在自身页面生效，不要当全局用：

| 位置 | 令牌 | 说明 |
| --- | --- | --- |
| `src/styles/profile.css` 的 `.profile-page` | `--profile-*` | 个人中心的独立色板，比门户侧更亮（强调色 `#4f8cff`） |

## 二、样式文件与加载顺序

### 入口顺序（`src/main.ts`）

导入顺序**就是**覆盖顺序，越靠后越优先：

```ts
import 'ui_73info/styles.css'          // 1. 组件库的令牌与底座
import './styles/user.css'             // 2. 门户侧（内含 9 个 @import）
import './styles/unified-top-card.css' // 3. 统一顶部卡片
import './styles/dev.css'              // 4. 开发者侧（内含 5 个 @import）
```

外加两处**按需加载**，只在对应组件挂载时才注入：

| 触发位置 | 加载的文件 |
| --- | --- |
| `src/views/HomeView.vue` | `src/styles/home.css`（2400 行，首页专用） |
| `src/components/AppToast.vue` | `src/styles/toast.css` |

### ui_73info 怎么接的

自研组件库 `ui_73info` **已经替换掉本端的 Element Plus**（**[架构与组件清单](../../ui_73info/doc/架构.md)**）：
`element-plus` 依赖与 `<el-*>` 标签都已移除，图标改从库里取（59 个预置图标组件，与
`@element-plus/icons-vue` 同名），`ElMessage` / `ElMessageBox` 换成 `TMessage` / `TMessageBox`。
它与上面这套样式**并存、互不干扰**：

- **主题属性**：`<html>` 上的 `data-73-theme`，只有 `portal` 与 `dev` 两个值
  （对应第一节的两套视觉体系）。**由路由守卫统一设置**
  （`src/router/index.ts` 的 `beforeEach`，判据是既有的 `isDeveloperRoute`），
  页面自己不要去写它——写在 `<html>` 上，一个页面写错会连累它下面的所有 `T*` 组件。
- **样式边界**：`ui_73info/styles.css` 只声明 `--73-*` 令牌与 `.t73` 类名空间，
  **不碰 `--dev-*` / `--portal-*` / `--profile-*`**。
- **写哪一套令牌**：页面自己的颜色、圆角、字号照第三节用本文件的令牌；
  凡是**库组件内部**的规格（控件高度、控件圆角、描边、状态色、表头底色）都走库的
  `--73-*`，不要再给库组件写 `--dev-*` 覆盖——那些变量已经没有任何组件在读。
  真实写法见 `src/styles/dev-base.css` 顶部「开发者页统一表格皮肤」那段注释。
- **全站已经没有任何 `ElConfigProvider` 包装**：本库的固定文案是中文硬编码，没有 locale 层，
  所以迁移时逐个去掉而不是留着「以后可能要用」。子组件若将来真需要语言包，再单独讨论。
- **迁移期那份 `ui_73info/alias.css`（旧变量名 → `--73-*` 的桥接层）全程没有引过**，
  现在也没有引：页面已经在直接用 `--73-*`。理由见
  [ui_73info/doc/架构.md](../../ui_73info/doc/架构.md) 第七节。

### 组件库怎么接的（易踩坑）

`vite.config.ts` 里只留了 `unplugin-vue-components` 的 `Components()`，默认只扫本项目的
`src/components`——**它不再负责 UI 库**（原来的 `AutoImport` 与 `ElementPlusResolver` 已随
element-plus 一起删除）。库组件一律按需具名导入：`import { TButton, TIcon } from 'ui_73info'`。

**库是 `link:` 进来的源码，不是构建产物**，所以有三处必须一起对待：

- `vite.config.ts` 的 `resolve.dedupe: ['vue']` 与 `optimizeDeps.exclude: ['ui_73info']`
  （后者是因为它发 `.vue` 源码，预打包会让 HMR 失效）。
- `tsconfig.app.json` 里 `vue` / `vue/*` 的 paths 钉到宿主那份 `./node_modules/vue`。
  只改 vite 不改 tsconfig，类型侧会出现两个 `Component` / `Ref`，「跨包传组件」的写法全报错。
- `manualChunks` 里给 `'/ui_73info/'` 单独分一块 `ui-73info`；它的真实路径在
  `node_modules` 之外，不挑出来就会落进 `vendor` 兜底。

**组件只认 `--73-*` 令牌，暴露的 prop 是语义而不是颜色**（`tone="success"` 而不是 `tone="green"`）。
要给某处组件换外观，先用它的 prop；prop 表达不了的再改页面自己那层的令牌。
**不要覆写 `.t73-*` 内部实现**——那是库的私有类名空间。

## 四、字体与排版

### 实际生效的字体（重要）

代码里声明了三套字体栈，但**仓库里没有任何 `@font-face`，也没有字体 CDN 引用**，所以声明的 Web 字体一个都不会加载：

- `src/styles/resource-core.css` 给 `body` 声明 `'Space Grotesk', 'Noto Sans SC', sans-serif`。这是**实际生效**的那一条。
- `src/styles/dev-base.css` 给 `:root` 声明 `'IBM Plex Sans', 'PingFang SC', 'Noto Sans SC', ...`。`body` 自己有声明，所以 `:root` 这条**不会作用到正文**——写着 IBM Plex Sans，实际看不到它。
- 代码块另用 `'IBM Plex Mono', 'SFMono-Regular', Consolas, monospace`（`rich-text-code.css`）。

结论：当前渲染结果是操作系统默认无衬线字体（Windows 上通常是微软雅黑）。想真正用上 Space Grotesk / IBM Plex，需要先补齐字体文件或 CDN，那是另一次改动的范围，改之前请先确认。

### 排版口径

- **没有设置全局基准字号**，浏览器默认 16px 起步，实际字号靠各页面显式声明。
- 正文主力是 `13px`，次要说明用 `12px`，标签与角标用 `11px`，卡片标题 `14px–18px`。新写页面请落在这个区间，不要引入 `10px` 以下或 `20px` 以上的新档位。
- 金额与计数用 `font-variant-numeric: tabular-nums`，避免数字跳动（`App.vue`、`InvoiceApplyDialog.vue` 都有先例）。
- 大写英文角标配 `letter-spacing`（常见 `0.08em` / `0.12em`）。
- **副标题非必要不用**：标题下不再顶一行装饰性副标题或灰字说明，只有承载必要信息（状态、倒计时、口径、必填提示）时才保留。判断标准是「去掉后信息是否缺失」，不是「版面是否显得空」；卡片头或分组头已经写出名字的，不要另起一行重复它。

### 圆角与间距

圆角按实测使用频次排序：胶囊 `999px`（最多的形态，用于标签与按钮）、`12px`、`8px`、`18px`、`10px`、`14px`、`16px`。**新代码从 `12px`（卡片）/ `10px`（小控件）/ `8px`（内嵌块）/ `999px`（胶囊）里选**，不要再引入新的圆角值。

间距：门户侧栅格 `gap: 14px`，开发者侧 `.dev-grid` / `.dev-page` 用 `gap: 24px`。

## 五、布局骨架与尺寸

### 外壳（`src/App.vue`）

```
.app-shell
└── .app-content
    └── el-scrollbar.app-scrollbar
        └── .app-view-container          ← :class 上加 --no-footer 控制页脚
```

滚动发生在外壳的 `el-scrollbar` 上。**页面内不要再套一层滚动容器**，否则页内 `sticky` 会失效。

### 容器宽度

| 位置 | 宽度 |
| --- | --- |
| 门户外壳 `.portal-shell` | `min(1280px, calc(100% - 24px))`，居中 |
| 门户两栏 `.portal-layout` | `minmax(0, 1.58fr) minmax(300px, 0.72fr)`，右栏 `position: sticky; top: 86px` |
| 开发者页 `.dev-page` | `min(1120px, 100%)`，居中 |

写新页面时**从上面这套里继承容器宽度**，不要再自造 `max-width`。

### 卡片形态

门户卡片统一是「`--portal-panel` 底 + `1px solid var(--portal-border)` 描边 + `var(--portal-shadow)`」，悬浮时换成 `--portal-shadow-hover`。开发者卡片用 `--dev-surface` + `--dev-shadow`。

## 六、响应式与移动端

> 这一节取代了原先登记在 `doc/README.md` 待补清单里的 `移动端适配.md`，两者合并为一处。

### 约定的断点

**新增代码只用这四个断点**（`AGENTS.md` 第 6 节的要求）：

| 断点 | 用途 |
| --- | --- |
| `980px` | 门户与开发者主布局由多栏转单栏 |
| `900px` | 导航转移动端形态、侧栏折叠 |
| `780px` | 次级多栏结构收窄 |
| `640px` | 触屏档：按钮撑满、字号下调、弹窗全屏化 |

### 现状与目标的差距（照实记录）

现有样式里共有 **116 处媒体查询、23 个互不相同的断点值**，散布在 `200 / 360 / 420 / 480 / 520 / 560 / 600 / 640 / 700 / 720 / 760 / 780 / 820 / 860 / 900 / 901 / 920 / 960 / 980 / 1080 / 1100 / 1180 / 1200px`。其中 `1180 / 960 / 900 / 780` 混用在 `components/PortalTopNav.vue`，各页面另有一套自己的数字。

**收敛到四个约定断点是存量债，不是新代码的许可。** 不要因为「别人也这么写」再加一个新断点；要动老页面时，顺手把它并到最近的约定断点上。

### 移动端硬要求

- **触摸目标不小于 `44px`**：低于 `640px` 时，按钮、列表项、菜单项要显式写 `min-height: 44px`（`profile.css`、`MessagesView.vue`、`RequirementConversationModal.vue` 都有先例，注释里也写明了这条约定）。
- **安全区**：贴底或贴边的固定元素要用 `env(safe-area-inset-*)`，目前用在 `components/PortalMobileDock.vue`、`components/MobileResourceList.vue`、`styles/toast.css` 等处。
- **交付前必须在 `320 / 375 / 414px` 三个宽度实测无横向滚动。**
- 移动端专用组件：`components/PortalMobileDock.vue`（底部导航坞）、`components/MobileResourceList.vue`（资源列表移动版）。新页面优先复用它们，不要重写一套。

## 七、新增页面必须遵守的规则

1. 先定体系（门户 / 开发者），再动笔；只使用该体系已有的令牌。
2. 容器宽度从第五节的现成值里选，不自造。
3. 颜色只写令牌，不写裸十六进制——**例外**是本文件登记为「页面级令牌」的那几个页面。
4. 圆角与字号从本文件给出的档位里选。
5. 需要改库组件外观时，先用它的 prop（`tone` / `variant` / `size`），prop 表达不了的再改页面自己那层的令牌；不要覆写 `.t73-*` 内部实现。
6. 页面内不套滚动容器，滚动交给外壳。
7. 响应式只用 980 / 900 / 780 / 640 四个断点。
8. 富文本渲染必须经 `src/utils/sanitizeHtml.ts`（DOMPurify）净化，URL 走白名单校验；后端还有一道 ammonia。**不要绕过。**
9. 标题下不顶装饰性副标题——副标题只在承载必要信息（状态、倒计时、口径、必填提示）时保留，见第四节排版口径。

- [ ] 容器宽度是否复用了现成值？
