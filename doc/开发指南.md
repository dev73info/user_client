> **覆盖**：命令、Node 版本要求、dev 代理、本地自动登录、环境变量、测试、依赖顺序。
> **不覆盖**：目录与路由的职责 → [架构.md](架构.md)；移动端适配与 SEO 脚本的细节 → `移动端适配.md`、`SEO与静态生成.md`（均待补）。
> 上级约定：[AGENTS.md](../../AGENTS.md)

## 一、命令

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 启动 dev server（默认 5173，被占用会自动递增） |
| `pnpm build` | 生产构建，串起 `generate:sitemap` → `type-check` → `build-only` |
| `pnpm build-only` | `vite build` + `scripts/generate-seo-pages.mjs` |
| `pnpm type-check` | `vue-tsc --build` |
| `pnpm preview` | 预览构建产物 |
| `pnpm test:unit` | vitest（`vitest.config.ts`，用例在 `src/__tests__/`） |
| `pnpm test:e2e` | playwright（`playwright.config.ts`，用例在 `e2e/`） |
| `pnpm lint` | `lint:oxlint` + `lint:eslint`，两者都带 `--fix` |
| `pnpm format` | prettier 写 `src/` |
| `pnpm generate:sitemap` | 只生成 sitemap |
| `pnpm submit:indexnow` / `pnpm submit:baidu` | 向搜索引擎提交 URL |

## 二、两个环境前提

1. **必须用 POSIX shell 跑。** `dev`、`build`、`build-only`、`type-check` 等脚本以 `env -u NODE_USE_ENV_PROXY ...` 开头，是 POSIX shell 的写法。本机默认 shell 就是 WSL `Ubuntu-22.04` 的 bash，`cd` 进仓库直接跑即可。
2. **Node 版本有下限**：`engines` 要求 `^20.19.0 || >=22.12.0`，包管理用 pnpm。

## 三、依赖顺序

`package.json` 里 `tags-wasm` 是 `link:../tags-wasm/pkg`。`pkg/` 被 `tags-wasm/.gitignore` 忽略、不进仓库，所以**新克隆的仓库必须先构建 `tags-wasm` 产出 `pkg/`，再 `pnpm install`**，否则这个依赖解析不到。重建方式见 [tags-wasm/doc/构建与集成.md](../../tags-wasm/doc/构建与集成.md)。

## 四、dev 代理

`vite.config.ts` 里硬编码了目标 `http://127.0.0.1:8080` 和一组代理前缀（全部带 `changeOrigin` 与 `ws`）：

```
/api  /auth  /coupons  /public/requirements  /realname  /requirements
/tickets  /payments  /settings  /resources/resources  /resources/tags  /uploads
```

这些是**后端真实路径**的前缀，不是 `src/shared/api/url.ts` 里的前端路径——两套前缀同时存在是这个项目最容易绕晕的地方。要新增代理前缀时，先确认它属于哪一套。

## 五、环境变量

| 变量 | 用途 |
| --- | --- |
| `VITE_API_BASE_URL` | 接口基地址，留空表示同源（走 dev 代理） |
| `VITE_ROUTER_MODE` | `history` 时用 history 路由，否则 hash |
| `VITE_DEV_AUTO_LOGIN_USERNAME` / `VITE_DEV_AUTO_LOGIN_PASSWORD` | 本地自动登录（见下） |
| `VITE_DEV_HOME_MOCK` | `true` 时开发者工作台总览改用 `src/shared/devHomeMock.ts` 的演示数据；也可在地址上加 `?mock=1` 临时打开。只在 dev 模式生效，build 与单测忽略 |
| `VITE_MOCK` | `true` 时整个客户端走假后端（`src/mock/`，见第七节）；也可在地址上加 `?mock=1` 临时打开、`?mock=0` 当场关掉。只在 dev 模式生效 |
| `VITE_MOCK_DELAY` | 假响应延迟毫秒数，默认 120；`?mockDelay=0` 可当场关掉 |

## 六、本地自动登录

复制 `.env.local.example` 为 `.env.local`，填两个变量：

```
VITE_DEV_AUTO_LOGIN_USERNAME=...
VITE_DEV_AUTO_LOGIN_PASSWORD=...
```

`.env.local` **不入库**，且只放可丢弃的开发账号。模板里预置的是一组演示账号凭据。

## 七、完整 mock（假后端）

不需要启动 8080 后端就能把客户端点一遍。代码在 `src/mock/`。

**怎么开**：`pnpm dev` 下在地址上加 `?mock=1`，或在 `.env.local` 里写 `VITE_MOCK=true`
（本机 `.env.local` 里是 `VITE_MOCK=false`；要整页走假后端就改成 `true` 再重启 dev server）。

**怎么确认生效**：控制台会打印一行 `[mock] 已启用：所有 /api 请求由假后端接管，当前身份「客户」…`，
同时页面左上角出现「MOCK」浮标。两者都没有，说明这个标签页里的 mock 没装上
（最常见的原因是标签页是改动之前打开的旧页面），硬刷新一次（Ctrl+F5）即可。

只有 dev 模式可能生效（`import.meta.env.MODE === 'development'`），`pnpm build` 与单测永远拿不到 mock；
在 build 产物里写 `?mock=1` 只会在控制台收到一句「不是 vite dev 模式，mock 不会生效」。

**两个身份**：左上角「MOCK」浮动面板切换 **客户 / 开发者**，点一下整页刷新。
身份记在 localStorage，`?mockAs=dev` 的优先级更高——想同时看两侧，就开两个标签页，
其中一个带 `?mockAs=dev`（点面板上的切换会清掉这个参数，避免「切不动」）。

**数据**：`src/mock/db.ts` 一份内存数据，两侧读的是同一批需求单 / 合同 / 支付单 / 资源，
所以「客户看到的进度」与「开发者看到的进度」永远对得上；`?mockAs` 只换视角，不换数据。
数据不持久化，刷新即回到初始状态。

**登录态**：mock 会按当前身份往 localStorage 写一个假令牌（`{header}.{payload}.mock`），
所以不需要账号密码就能进两个工作台。令牌不属于当前身份时会自动换掉，
因此「刷新一下又自动登录了」是预期行为；想停在未登录状态，就在浮标里登出之后不要刷新页面。

**覆盖范围**：

- 客户侧：发布需求 → 平台审核 → 发起/签署合同 → 定金 → 尾款 → 验收 → 评价 → 发票
- 开发者侧：需求大厅（可接取）→ 接单并绑定资源 → 版本/交付 → 我的接单 → 钱包与提现 → 保证金
- 通用页：账号设置、实名认证、积分签到、客服工单、优惠券、社区、团队（空态）

**没实现的接口**：GET 返回空数组、其余返回空对象，同时在控制台 `warn` 一次并记进浮动面板的清单。
口径是「够用但不假装」：空数组能保证页面不崩，缺口又一眼可见，比返回一份像真的一样的假数据安全。

**已知边界**（都不接通外部服务，只给占位结果）：爱签签署与预览、微信/支付宝/QQ 扫码与支付页、
真实客服长连接（`/api/support/conversations/ws` 换成空壳 WebSocket，只拦 `/api` 下的 ws，
Vite 的 HMR 连接正常放行）、资源标签树（wasm 解析口径不明，给空数组）、文件上传不落盘、
下载接口返回占位内容。

**关掉**：面板里的「关闭 mock」，或地址上加 `?mock=0`。两者都会把「本次会话明确关」写进
sessionStorage，优先级高于 `VITE_MOCK=true`，所以**不论 mock 是怎么开的都关得掉**；
代价是本次会话不再跟随环境变量，想恢复就加一次 `?mock=1`，或关掉标签页重开。
要连默认值一起改掉，就把 `.env.local` 改成 `VITE_MOCK=false` 并重启 dev server（改 `.env` 不会热更新）。

## 八、踩坑速记

- 改完 `tags-wasm` 的 Rust 源码必须重建 `pkg/`，否则前端仍跑旧的 WASM。
- `components.d.ts` 是生成物但入库，改代码后出现它的 diff 属正常。`auto-imports.d.ts` 已随 `unplugin-auto-import` 一起删除，不再生成。
- 401 失效令牌会自动登出并弹登录框，这是设计行为（改密后旧令牌即失效），排查时不要当成 bug。
